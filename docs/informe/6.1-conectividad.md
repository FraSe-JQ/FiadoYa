# 6.1 Conectividad

FiadoYa emplea una arquitectura física de tres servicios: frontend Angular en Nginx, backend Spring Boot sobre Java 21 y MySQL 8.4.7. Nginx sirve archivos estáticos y reenvía /api, /v3 y /swagger-ui al backend mediante la red web de Compose. El backend accede a MySQL por JDBC en la red database, declarada interna. Solo se publica el puerto HTTP del frontend en 127.0.0.1:4200. MySQL no dispone de puerto publicado.

La arquitectura lógica distingue presentación, aplicación/dominio y persistencia. El motor financiero es un conjunto de clases Java sin dependencias de HTTP ni JPA. Los diagramas editables se encuentran en [arquitectura](../arquitectura.md) y [trazabilidad de operaciones](../trazabilidad-operaciones.md).

Las solicitudes utilizan REST/JSON; la sesión se representa mediante JWT HMAC SHA-256, con una hora de expiración, identificador persistido y cookie HttpOnly SameSite Strict. Spring Security valida la sesión y el usuario. El registro público no crea administradores. El logout revoca las sesiones activas. Las mutaciones requieren CSRF; CORS limita el origen configurado. Las contraseñas se almacenan con BCrypt de coste 12.

La autorización comprueba rol, membresía de tienda y titularidad de cuenta en el backend. Las operaciones financieras son transaccionales, con bloqueo de cuenta, restricciones únicas e idempotencia. La base recibe importes y tasas decimales; no se delegan decisiones financieras al navegador.

Docker Desktop local constituye el entorno efectivamente ejecutado. La VM Ubuntu con TLS es un procedimiento preparado, no un despliegue realizado. Los requisitos orientativos de hardware y las instrucciones están en [despliegue](../despliegue.md). No se reportan pruebas de capacidad ni disponibilidad no ejecutadas.
